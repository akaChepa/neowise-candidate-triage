# Тестовое Neowise. AI-помощник для входящих заявок

Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

Нужен Node.js 20 или новее. Зависимостей и ключей нет.

\`\`\`sh
node server.mjs
\`\`\`

Откройте http://127.0.0.1:3000. Порт задаётся переменной \`PORT\`, таймаут модели — \`MODEL_TIMEOUT_MS\` (по умолчанию 300 мс).

## Тесты

\`\`\`sh
node --test triage.test.mjs
\`\`\`

14 тестов: валидация входа (пустой/пробельный/нестроковый text, битый JSON), успешный разбор, и все сбои модели (таймаут, ошибка, не-JSON, недопустимая тема, пустой черновик) с ожиданием \`manual_review\`.

## Что изменено

1. \`POST /api/triage\` принимает только JSON с непустым строковым \`text\`. Битый JSON, отсутствующее поле, нестрока, пустая строка и строка из пробелов → HTTP 400 \`{"status":"invalid_input"}\`. Тело ограничено 64 КБ.
2. Успех → HTTP 200 \`{"status":"ready","topic","draft"}\`, тема только из \`delivery|pricing|other\`, черновик непустой (обрезается по краям).
3. Ожидание модели ограничено 300 мс через \`AbortController\`. Таймаут, исключение имитатора, не-JSON, неподходящая тема или пустой черновик → HTTP 200 \`{"status":"manual_review","topic":null,"draft":null}\`.
4. Страница показывает тему и черновик при успехе. При \`manual_review\` — понятное сообщение менеджеру, предыдущий черновик очищается. Пустой ввод не отправляется на сервер. Добавлена защита от гонки запросов: показывается результат последнего запроса.
5. Имитатор \`mock-ai.mjs\` не изменялся.

## Где проверяется результат AI

В \`runModel()\` в \`server.mjs\`: ответ модели парсится и валидируется по схеме (\`parseModelResult\`) до отправки клиенту. Ни \`topic\` вне списка, ни пустой \`draft\` не попадают в ответ API.

## Что происходит при сбое

Менеджер видит «Нужен ручной разбор», черновик не подставляется (в том числе старый), API возвращает \`manual_review\` с \`null\`-полями — то есть пустой текст клиенту уйти не может.

## Какой AI использовался

Задание выполнялось с AI-ассистентом (генерация кода и тестов), вся логика проверена локальным прогоном тестов: \`14 pass / 0 fail\`.

## Польза для менеджера

Менеджер не тратит время на типовые обращения: разбор занимает секунды вместо минут, а при любом сбое модель не отдаёт пустой или выдуманный текст — заявка уходит на ручной разбор. Мерить: время на обработку одной заявки, доля заявок без ручной правки, число случаев, когда клиенту ушёл пустой черновик (цель — ноль).
